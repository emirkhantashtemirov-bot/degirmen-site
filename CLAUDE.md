# Degirmen Navoi - памятка для Claude

Репозиторий ПУБЛИЧНЫЙ: никаких паролей, ключей и личных данных в коде и в этом файле.

## Что здесь
- `index.html` - приложение заказов (PWA). Весь код приложения в `<script id="appjs" type="text/x-app">`. Проверка синтаксиса:
  `node -e "const s=require('fs').readFileSync('index.html','utf8');const m=s.match(/<script id=\"appjs\" type=\"text\/x-app\">([\s\S]*?)<\/script>/);new Function(m[1])"`
- Новые блоки вставлять перед строкой `boot().then(()=>sb.auth.onAuthStateChange(`. Расширять функции обёрткой `{const _x=fn;fn=function(){...}}`.
- Помощники: `S` (состояние), `LS`, `sb` (Supabase), `t()` и `T.ru/kk/en` (тексты на 3 языках), `toast`, `render`, `itemOf`, `op_` (карточка товара), `isAdm`, `staff`.
- Меню одной лентой: секции `.csec#cat-<код>`, вкладки `.cats` переключаются по прокрутке, `setCat(k)` листает к разделу.
- `brewsell/` - бренд-сайт кофе Brewsell (three.js r160 с jsdelivr, 3D-сцены), `label.jpg` - наклейка.
- `avto/` - «Автоучёт» (учёт машин, 3D, мини-игра `drive.html`). `guard/` - APK слежения за планшетами. `glm/` - песочница.
- Деплой: push в `main` → сервер подтягивает изменения раз в минуту. Коммиты с трейлерами Co-Authored-By и Claude-Session.

## База (Supabase, проект nctmbakzbzzkygndaklr)
- Оплата: Edge Function `epay` (код в `supabase/functions/epay`), доступы ePay только в закрытой `paloma_config` (epay_*). Заказ: `pay_method` cash|online, `pay_status` none|pending|paid|failed|refunded. Онлайн-оплату отмечает только сервер после проверки статуса в банке. Неоплаченные заказы не идут на кухню. Возврат - `can_refund()` (разработчик + список `refunders`).
- Цены: Paloma главная. Триггер на `paloma_items` обновляет `menu_items.data.p` и `menu_options.price` (исключения - `price_sync_off`), смена цены в админке уходит в Paloma через `paloma-write` op price. Тестовая позиция `air` (data.test) видна только админам.
- Telegram-бот @degirmennavoiconsult_bot: вебхук на `tg-hook` (закупы «Дегирмен учёт»: bot_buys/bot_buy_items, источники cash/kaspi/biz/own, доступ сотрудников tg_staff по кнопке владельца), остальное tg-hook передаёт в `nexus`. Отчёты: cron buy-daily 22:30, buy-month 1-го в 09:10. В приложении: Финансы → «Закупы» (buy_report), закупы из бота в «Отчёте дня» (fin_day.bot, «Из кассы» вычитается из остатка).
- Отчёт дня через бота (только владельцы, код `supabase/functions/tg-hook/report.ts`): меню /otchet (кнопки дня, ждёт фото 15 мин, статус wait в bot_day_drafts) или фото листа с подписью «отчёт 5 ноября» → fin-ocr (ИИ Qwen через Groq) → черновик `bot_day_drafts` → кнопки «Записать» / «Записать и закрыть день» (RPC `fin_as`, только service_role). Текст «отчёт вчера» - общий отчёт по разделам. Дата закупа из текста («вчера», «5 ноября»): владельцы до 62 дней назад, сотрудники до 7.
- Двойной учёт закупа (бот + та же строка в «Отчёте дня»): в приложении `finDups()` (название по первым 4 буквам + сумма ±20%, или та же сумма ±2%), предупреждение под строкой, кнопки «Тот же - убрать» / «Это другой» (`fin_lines.dup_ok`), повторное нажатие «Сохранить». В боте `findDups` в report.ts: кнопка «Записать без повторов» и строка в отчёте дня.
- Лист кассы (fin-ocr, код `supabase/functions/fin-ocr`): деньги кассы - колонки «цена» и «цена Итого»; сумма в названии без итога -> `ask` (кнопки ТОО / Свои / Касса; ТОО и свои пишутся в bot_buys как «Лист кассы» через fin_save p.ask, касса - строкой закупа); в З/П любые числа - авансы, время - приход (`fin_arrivals`, p.arrivals); «Дегирмен: закуп» -> grp degirmen (деньги ТОО, платят в конце месяца), тару не считать; «+N» к выручке/остатку игнорировать; итоги листа сверяются (unsure). Опоздания: `arrivals_stats`, начало смен в paloma_config.shift_start, карточка в Финансы → Месяц и в месячном отчёте бота.
- Обучение сотрудников: при первом входе кассира/админа (localStorage dn_tut_<uid>), повтор: Касса → «Обучение».
- `menu_items` (цены в `data.p`, `data.pal` - id в Paloma; `data.pack/nf/gi` - пачка Brewsell `bw`, без бесплатного кофе и добавок), `menu_options`, `orders` (триггер `orders_guard` пересчитывает цену на сервере), `profiles`, `account_sanctions`.
- Функции разработчика защищены `is_dev()` (только владелец). Служебные функции - в схеме `private`.
- execute_sql: запросы с DELETE/REVOKE/DROP отменяются - проектировать без них. Тесты - DO-блок с `set_config('request.jwt.claims',...)` и `raise exception 'REPORT ...'` (всё откатывается).

## Правила владельца
- Только короткие тире «-», длинные тире не использовать нигде.
- Пароли и ключи не просить и не присылать, ключи только на сервере. Платежи вводит только владелец.
- Письма и сообщения - только по явной просьбе.
- Чужой код/дизайн (Drinkit и др.) не копировать - только идеи, реализация своя.
- GLM/Gemini - только поиск багов, без правок кода и живой базы.
- Владелец не программист: объяснять без жаргона, по-русски.
